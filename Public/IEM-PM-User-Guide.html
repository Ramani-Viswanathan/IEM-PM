IEM-PM · User Guide

Turn your project data into an evidence-based gap audit

No dashboard, no login, no server. IEM-PM runs inside Claude Code, reads what you point it at, and hands back one report you open in a browser. This page is the whole manual — for Project Managers, Program Managers, and PMO leads who want to run an audit without touching Python.

First audit: roughly 2–4 hours, most of it Claude reading and reasoning.
Repeat audits: about 30 minutes.

Prerequisites

Before you start

IEM-PM's one rule is no baseline, no audit — it will not guess at a standard you haven't given it. Everything below has to exist before you ask for an audit.

  • Standards in knowledge/ PMBOK, PRINCE2, ISO 21502, or your own internal methodology — whatever your organization actually follows.
  • A completed PMO Data Charter Start from assets/PMO_DATA_CHARTER_template.md. This is the step that tells IEM-PM what your fields mean — skip it and it will still run, but every finding gets flagged as provisional.
  • Delivery evidence gathered Schedules, RAID logs, status reports, steering packs — whatever you have on hand for the project, program, or portfolio in scope.
  • Claude Code, open in this repository This is how you actually run the audit — there's no separate app to install.

Nothing you hand it gets changed. IEM-PM only reads your standards, your Charter, and your evidence. The only thing it ever writes is inside your project's own reports/ folder, inside Audit/<YourProjectName>/ — your source data is never touched.

Step by step

The audit workflow

Six stages, always in this order. You only type anything in Steps 2 and 3 — the rest is instructions to Claude Code.

1
You confirm

Standards are in place

Check that knowledge/ actually contains the standards you're auditing against. If it's empty, the audit stops before it starts — that's intentional, not a bug.

2
You write

Complete the Data Charter

Fill in the template: give each artifact an ID (ART-001, ART-002...), define what your fields mean (what does "on track" mean in your steering pack?), and set materiality — what's big enough to matter. This is the only step where your judgment, not the engine's, sets the rules.

Then ratify it — literally type a name, role, and date at the bottom, and save it as Audit/<YourProjectName>/reports/PMO_DATA_CHARTER_ratified.md. That filename is what makes it real rather than a draft.

3
You gather

Assemble delivery evidence

Create a folder for this project under Audit/ — any name you like, e.g. Audit/Acme-Q3-2026/ — and put your schedules, logs, and reports inside an evidence/ folder there: Audit/Acme-Q3-2026/evidence/. Real files, not summaries — the audit cites exact locations, so it needs the originals. Export first if your data lives in Jira, ADO, or Primavera — the engine doesn't log into tools. The engine creates a matching reports/ folder next to your evidence/ folder automatically — you don't create that part yourself.

Before it starts scoring anything, IEM-PM checks whether your evidence set is even enough to support a credible audit. This runs automatically, before Step 4 — you can't skip it and you can't argue with it. It maps your artifacts to 7 categories, then applies 3 rules.

Category Domain Mandatory?
A — AuthorizationCharterRequired
B — ScopeScope2 of B/C/D
C — CostCost2 of B/C/D
D — ScheduleSchedule2 of B/C/D
E — RiskRiskRequired
F — Change ControlChange control—
G — Performance MonitoringReports—
  1. Rule 1 — Mandatory categories. A and E must each have at least one artifact. At least two of B, C, D must also be covered. Miss any of this → the audit halts. No exceptions, nothing you can override.
  2. Rule 2 — Minimum breadth. At least 4 of the 7 categories must be represented overall.
  3. Rule 3 — Minimum artifact count. At least 3 distinct artifacts. One file cannot cover multiple categories by itself, no matter how much it contains.

If your evidence fails this check, you don't get a report. You get a ScopeLimitation_Notice instead — it names exactly which categories are missing and what to add. No score gets calculated on evidence that can't support one.

4
Claude Code runs

The audit itself

Ask Claude Code to run the intelligence-engine skill against your Charter and evidence. It reads everything, compares it to your standards, and writes exactly one file: Audit/<YourProjectName>/reports/audit_manifest.md.

5
Claude Code runs

Convert and validate

Ask Claude Code to turn the Manifest into your report — it runs the two conversion steps for you. If you'd rather do it yourself, the commands are underneath.

For reference — two commands, run from skills/intelligence-engine/scripts/ (both scripts default their output next to the input file you give them, inside your project's own reports/ folder, so --output/--output-html/--output-txt are optional): python manifest_to_findings.py --manifest ../../../Audit/<YourProjectName>/reports/audit_manifest.md python render.py --canonical ../../../Audit/<YourProjectName>/reports/IEMPM_AuditGap_Report_DDMMYY_HHMM.json --template ../assets/report_template.html
6
You read

Open the report

Inside Audit/<YourProjectName>/reports/ — the rendered .html file. Double-click it, or open it in any browser. That file is the entire interface. Nothing to log into, nothing to configure.

Interpreting the output

Reading your report

The report has ten sections. Most people only need four of them on a first pass — here's what each one is actually telling you.

Section What it tells you Read it when
Executive Summary Total findings, and the Reporting Integrity Score out of 100 — a deterministic score, not an opinion. Always, first
Gap Register Every individual finding: what's wrong, which of the seven gap types it is, and the evidence behind it. Before a gate review
Root Cause Analysis Where each gap actually started — one of seven origins (Capture, Ownership, Tooling, and so on). The cause, not the symptom. When the same issue keeps recurring
Recommended Actions / Roadmap What to fix, grouped by root cause and ordered by severity. Right after the Gap Register
After the report

Remediate, then re-audit

The report is a starting point, not a verdict. A 30-day rhythm that works:

W1

Fix what's Critical or Major

Close every Severity 5 and 4 finding first. These are the ones that threaten delivery outcomes, not just tidiness.

W2

Fix the loudest root origin

Look at Root Cause Analysis. If most gaps trace to Ownership, assign owners. If it's Capture, fix the templates. Treat the cause, not each symptom individually.

W3

Close the Missing gaps

Either establish the process the standard actually requires, or update the Charter if it turns out the artifact was never really in scope.

W4

Re-audit with the same Charter

Same Charter, same standards, fresh evidence. Save the new run as audit_manifest_v2.md → findings_v2.json → report_v2.html, so nothing overwrites the baseline you're measuring against.

Measure the delta, not just the score. Did the Reporting Integrity Score improve? Did gap density drop? Did the root-origin distribution actually shift, or did the same cause just move to a new artifact?

Who's asking

By role

The workflow above doesn't change. What you do with the result does.

Project Manager

Before your next gate

  • Run it on your own project a few days ahead of a steering committee or stage gate.
  • Use the Gap Register to fix data problems before the meeting, not explain them during it.
  • Treat Recommended Actions as your punch list, not the auditor's opinion of you.
Program Manager

Patterns across projects

  • Run one audit per project in the program, using the same Charter for all of them.
  • Compare Root Cause Analysis across projects — a root origin repeating in most of them is a program-level fix, not five separate ones.
  • Escalate root causes, not individual findings, to your PMO.
PMO

Governance, standardized

  • Own the Charter — write it once, ratify it, and require every audit in the portfolio to use it.
  • Own the standards in knowledge/ so every project is measured against the same baseline.
  • Track the Reporting Integrity Score over time as a governance health metric, not a one-off grade.
Before you ask

Good to know

It stopped and said "no baseline, no audit" — is that broken?
No. It means knowledge/ doesn't have any standards in it yet. Add the PDF or document you actually follow and run it again.
I didn't ratify a Charter — can I still run it?
Yes, but it runs PROVISIONAL: every single finding carries a caveat that it rests on an assumed, not agreed, interpretation of your data. Fine for a first look, not for a governance decision.
Will it change or move any of my files?
No. It only reads your standards, Charter, and evidence, and only ever writes inside your project's own reports/ folder, next to evidence/.
Do I need to learn Python or the terminal?
No — ask Claude Code to run Step 5 for you. The commands exist for anyone who wants to run them by hand, not as a requirement.
Is there a live dashboard I should be looking for?
No, and there isn't meant to be. report.html is the whole interface — open it, read it, share the file itself with whoever needs it.
I'm new — how do I audit a project's artifacts against PMI standards?
  • Create Audit/<ProjectName>/evidence/ and drop your artifacts in (schedules, RAID logs, charters, status reports, etc.).
  • Make sure knowledge/PMI/ has real PMI standard documents in it — nothing runs without a baseline.
  • Open Claude Code, point it at skills/intelligence-engine/SKILL.md, and ask it to audit Audit/<ProjectName>/evidence/ against PMI.
  • Review the Charter it proposes (scope + standards) and ratify, edit, or decline it.
  • Let it run to completion — reports land in Audit/<ProjectName>/reports/.

What it audits: your delivery artifacts against the real PMI standard text you dropped into knowledge/ — clause by clause, never from memory.

Which gaps: one of 7, closed taxonomy — Missing · Ignored · Disconnected · Untrusted · Underutilized · Misclassified · Divergent — each also traced to one of 7 root origins (Capture · Integration · Definition/Taxonomy · Ownership · Process/Cadence · Tooling · Behavior).

What sequence it follows: Baseline → Charter (proposed → ratified) → Define → Measure → Classify → Trace → Engineer & Score → Synthesize (Manifest) → JSON (validated) → Render → Final Summary.

What does "auditing the gap" actually mean — what is it comparing?

Not your project's performance — whether the data PMI requires you to capture and use actually exists, is complete, trusted, and used correctly in your evidence. For every checkable criterion in the standard, it asks "does this evidence satisfy it?" A "no" becomes one of:

  • Missing — required, doesn't exist anywhere in your evidence.
  • Ignored — exists, but isn't acted on.
  • Disconnected — exists, but doesn't tie to another artifact it should reference.
  • Untrusted — exists, but contradicts itself or another source.
  • Underutilized — exists and is correct, but isn't used to inform decisions.
  • Misclassified — exists, but tagged/categorized wrong against the standard's taxonomy.
  • Divergent — exists, but deviates from the standard's defined process/format without documented rationale.

So the check is: standard's required data element → present in evidence? → if yes, is it trustworthy, connected, used, correctly classified, and consistent with the standard's process? Every "no" is one finding, one gap type, traced to a root cause.

If something fails

Symptom Likely cause Fix
BASELINE_ABSENT No standards in knowledge/ Drop your methodology files in and run it again.
Invalid gap_type The Manifest used wording that doesn't match one of the seven gap types exactly Ask Claude to correct the wording — it must match exactly.
Unknown artifact An evidence bullet cites an artifact ID that was never declared in the Charter Add the artifact to the Charter, or remove the bullet.
Claude offers to run the scripts itself A reminder got missed — judgment and execution are meant to stay separate Tell it: "You write the Manifest. I run the scripts."
You get a Scope Limitation Notice, not a report Your evidence set failed the 7-category coverage check (see Step 3) — too thin to support a credible audit Read the notice's Coverage Analysis table, add artifacts for the categories it flags, and re-run.
Never break these

The 5 rules

  1. No ratified Charter, no audit. Never let it guess what your data means.
  2. Every finding needs evidence. No quote, no absence, no finding.
  3. It judges, you run the software. Claude writes the Manifest; you (or Claude, on request) run the two scripts.
  4. Read-only, always. Only the Manifest and your project's own reports/ folder ever get written.
  5. Local-first. No cloud calls, no databases — everything stays on your machine.
