Turn your project data into an evidence-based gap audit

Prerequisites

Before you start

IEM-PM's one rule is no baseline, no audit — it will not guess at a standard you haven't given it. Everything below has to exist before you ask for an audit.

  • Standards in knowledge/ PMBOK, PRINCE2, ISO 21502, or your own internal methodology — whatever your organization actually follows.
  • A completed PMO Data Charter Start from assets/PMO_DATA_CHARTER_template.md. This is the step that tells IEM-PM what your fields mean — skip it and it will still run, but every finding gets flagged as provisional.
  • Delivery evidence gathered Schedules, RAID logs, status reports, steering packs — whatever you have on hand for the project, program, or portfolio in scope.
  • Claude Code, open in this repository This is how you actually run the audit — there's no separate app to install.

Nothing you hand it gets changed. IEM-PM only reads your standards, your Charter, and your evidence. The only thing it ever writes is inside reports/ — your source data is never touched.

Step by step

The audit workflow

Six stages, always in this order. You only type anything in Steps 2 and 3 — the rest is instructions to Claude Code.

1
You confirm

Standards are in place

Check that knowledge/ actually contains the standards you're auditing against. If it's empty, the audit stops before it starts — that's intentional, not a bug.

2
You write

Complete the Data Charter

Fill in the template: which artifacts count as evidence, what your fields mean (what does "on track" mean in your steering pack?), and what's in scope. This is the only step where your judgment, not the engine's, sets the rules.

3
You gather

Assemble delivery evidence

Put the schedules, logs, and reports somewhere Claude Code can read them. Real files, not summaries — the audit cites exact locations, so it needs the originals.

4
Claude Code runs

The audit itself

Ask Claude Code to run the intelligence-engine skill against your Charter and evidence. It reads everything, compares it to your standards, and writes exactly one file: reports/audit_manifest.md.

5
Claude Code runs

Convert and validate

Ask Claude Code to turn the Manifest into your report — it runs the two conversion steps for you. If you'd rather do it yourself, the commands are underneath.

For reference — two commands, run from skills/intelligence-engine/scripts/: python manifest_to_findings.py --manifest ../../../reports/audit_manifest.md --output ../../../reports/findings.json python render.py --canonical ../../../reports/findings.json --template ../assets/report_template.html --output-html ../../../reports/report.html --output-txt ../../../reports/report.txt
6
You read

Open the report

reports/report.html — double-click it, or open it in any browser. That file is the entire interface. Nothing to log into, nothing to configure.

Interpreting the output

Reading your report

The report has eleven sections. Most people only need four of them on a first pass — here's what each one is actually telling you.

Section What it tells you Read it when
Executive Summary Total findings, and the Reporting Integrity Score out of 100 — a deterministic score, not an opinion. Always, first
Gap Register Every individual finding: what's wrong, which of the seven gap types it is, and the evidence behind it. Before a gate review
Root Cause Analysis Where each gap actually started — one of seven origins (Capture, Ownership, Tooling, and so on). The cause, not the symptom. When the same issue keeps recurring
Maturity Assessment Your position on PMI's OPM3 model. PENDING_BRIDGE right now means this specific calibration isn't done yet — expected, not broken. Once the bridge is ratified org-wide
Recommended Actions / Roadmap What to fix, grouped by root cause and ordered by severity. Right after the Gap Register
Who's asking

By role

The workflow above doesn't change. What you do with the result does.

Project Manager

Before your next gate

  • Run it on your own project a few days ahead of a steering committee or stage gate.
  • Use the Gap Register to fix data problems before the meeting, not explain them during it.
  • Treat Recommended Actions as your punch list, not the auditor's opinion of you.
Program Manager

Patterns across projects

  • Run one audit per project in the program, using the same Charter for all of them.
  • Compare Root Cause Analysis across projects — a root origin repeating in most of them is a program-level fix, not five separate ones.
  • Escalate root causes, not individual findings, to your PMO.
PMO

Governance, standardized

  • Own the Charter — write it once, ratify it, and require every audit in the portfolio to use it.
  • Own the standards in knowledge/ so every project is measured against the same baseline.
  • Track the Reporting Integrity Score over time as a governance health metric, not a one-off grade.
Before you ask

Good to know

It stopped and said "no baseline, no audit" — is that broken?
No. It means knowledge/ doesn't have any standards in it yet. Add the PDF or document you actually follow and run it again.
I didn't ratify a Charter — can I still run it?
Yes, but it runs PROVISIONAL: every single finding carries a caveat that it rests on an assumed, not agreed, interpretation of your data. Fine for a first look, not for a governance decision.
Will it change or move any of my files?
No. It only reads your standards, Charter, and evidence, and only ever writes inside reports/.
Do I need to learn Python or the terminal?
No — ask Claude Code to run Step 5 for you. The commands exist for anyone who wants to run them by hand, not as a requirement.
Is there a live dashboard I should be looking for?
No, and there isn't meant to be. report.html is the whole interface — open it, read it, share the file itself with whoever needs it.
